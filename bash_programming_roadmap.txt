This roadmap focuses on Bash programming syntax and language concepts after learning basic Linux.
It intentionally excludes Linux administration, troubleshooting, and lists of Linux commands.

============================================================
IMPORTANT CONSTRUCTS TO UNDERSTAND
============================================================

Understand the purpose and differences between these constructs:

- [ ]       Traditional test command
- [[ ]]     Bash conditional expression
- (( ))     Arithmetic evaluation
- $(( ))    Arithmetic expansion
- { }       Command grouping
- ( )       Subshell grouping
- ${ }      Parameter expansion
- $( )      Command substitution
- <( )      Process substitution

IMPORTANT DIFFERENCES TO STUDY

- return vs exit
- return vs echo
- $? vs $!
- $@ vs $*
- = vs ==
- -eq vs ==
- && vs -a
- || vs -o
- ! vs !=
- Single quotes vs double quotes
- $( ) vs <( )
- for vs while vs until
- local vs global variables
- Indexed arrays vs associative arrays
- Sourcing vs executing a script
- Parent shell vs subshell

IMPORTANT BEHAVIOURS TO UNDERSTAND

- Why does $? change after every command?
- Why can an unquoted variable split into multiple arguments?
- Why does a variable modified inside a subshell not change in the parent shell?
- Why does return not return a string?
- Why does Bash treat 0 as success?
- Why can ((count++)) produce a nonzero exit status?
- Why can a pipeline execute commands in subshells?
- Why can an array lose its elements when passed incorrectly to a function?
- Why can set -e terminate a script unexpectedly?

============================================================
HOW TO STUDY EACH TOPIC
============================================================

For every concept, follow this learning pattern:

1. Understand what the concept means.
2. Learn its syntax.
3. Understand how it works.
4. Learn its variations.
5. Understand common mistakes.
6. Write 5–10 small programs using that concept.
7. Combine it with previously learned concepts.

Example: When studying functions:

- Create a function without arguments.
- Create a function with one argument.
- Add multiple arguments.
- Use local and global variables.
- Return success and failure statuses.
- Return actual data using printf.
- Capture function output.
- Pass arrays to functions.
- Build a function that validates input and returns an appropriate status.

============================================================
THREE LEARNING STAGES
============================================================

STAGE 1 — CORE PROGRAMMING (Topics 1–8)

Variables, data types, conditions, operators, loops, arrays and input/output.

Goal:
Write small programs independently without referring to examples.

STAGE 2 — STRUCTURED PROGRAMMING (Topics 9–12)

Functions, arguments, return values, parameter expansion, quoting and pattern matching.

Goal:
Write reusable scripts with proper argument handling and modular structure.

STAGE 3 — ADVANCED BASH (Topics 13–15)

Execution behaviour, subshells, pipelines, redirections, error handling, traps and debugging.

Goal:
Understand why scripts behave the way they do and write reliable Bash programs.

============================================================
LEARNING NOTES
============================================================

- Use Bash 5.x for learning and understand which features are version-dependent.
- Learn Bash specifically, not only generic POSIX shell syntax.
- Do not jump into AWS automation, Kubernetes automation, Linux administration scripts or troubleshooting yet.
- You do not need to master every obscure Bash feature. Focus on the core concepts and their practical behaviour.
- Treat this document as a syllabus. Study one numbered section at a time, with explanations, examples, exercises and assignments before moving to the next section.
